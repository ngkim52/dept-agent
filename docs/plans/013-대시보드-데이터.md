# 013 - 대시보드 데이터 명세 (RAG 적재용)

> 목적: 대시보드가 보여주는 KPI 현황·뉴스·분석 데이터를 RAG(대용량 원문 검색)에 적재하기 위한
> 데이터 목록/형식 가이드. 현재 구현은 `src/lib/dashboard/kpis.ts`의 **예시 현황**을 사용하며,
> 아래 형식으로 데이터를 채워 넣으면 `getKpiStatuses()`만 교체하면 실측치가 반영된다.

## 1. KPI 현황 데이터 (핵심)

각 부서·KPI에 대해 다음 필드를 제공. 단위, 목표, 기준(전월), 상승/하락이 좋은지 방향이 중요하다.

| 필드 | 타입 | 설명 | 예시 |
|---|---|---|---|
| key | string | KPI 고유키 | `loss_ratio` |
| label | string | KPI 이름 | `보험금 손해율` |
| unit | string | 단위 | `%` / `억원` / `일` / `건` |
| value | number | 당월 실적 | `78.2` |
| target | number | 목표값 | `77.0` |
| baseline | number | 기준값(전월/전년) | `76.5` |
| goodWhen | "up"\|"down" | 값이 높을수록 좋은지 | 값↓이 좋으면 `down` |
| dept | string | 담당 부서 | `보험금 QA` |
| note | string | 현황 설명(LLM 분석 힌트) | 지급보험금 상승으로 목표 초과… |

### 예시 KPI 목록 (kat catalog)
- 보험금 손해율(`loss_ratio`, %) — 낮을수록 좋음
- 지급보험금(`pay_amount`, 억원) — 낮을수록 좋음
- 청구 처리 기간(`claim_days`, 일) — 낮을수록 좋음
- 자동심사 비율(`auto_rate`, %) — 높을수록 좋음
- 보험금 지급거절률(`reject_rate`, %) — 낮을수록 좋음
- 부정청구 탐지 건수(`anti_fraud`, 건) — 높을수록 좋음

### 적재 시 기준
- 월 단위 시계열 + 부서 태그 + KPI 정의(단위·방향)를 함께 문서화할 것
- note에는 "왜 목표를 벗어났는가" 원인 후보를 1~2문장으로 포함하면 LLM 분석 품질 향상

## 2. 뉴스 데이터

| 필드 | 타입 | 설명 |
|---|---|---|
| id | string | 고유키 |
| source | string | 출처 (금융감독원 / 생명보험협회 …) |
| tag | string | 분류(감독/규제/업계) |
| title | string | 제목 |
| date | string | YYYY-MM-DD |
| url | string(선택) | 원문 링크 |

- 운영 시 금융감독원 보도자료·생보협회 배포 API RSS로 자동 수집(`src/lib/news.ts#getNews` 교체 지점)

## 3. 하네스 일감 (자동, 별도 적재 불필요)

- 승인 대기 후보(`improvement_candidates.status=pending`)는 대시보드가 `/api/dashboard`에서 자동 노출
- 데이터 자체를 적재할 필요 없음 (에이전트 내부 상태)

## 4. 분석 데이터 (자동 생성)

- KPI 현황을 받아 cheap 모델이 `/api/dashboard`에서 생성 → 적재 불필요. LLM 미구성 시 휴리스틱 폴백.

## 납품 형식
아래 3개 컬렉션으로 RAGFlow에 문서 적재 권장 (문서 이름에 구분 표기):
1. `대시보드_KPI_YYYYMM.json` — KPI 현황
2. `대시보드_뉴스_YYYYMM.json` — 뉴스
3. `대시보드_기준.md` — KPI 정의(단위·방향) 설명

적재 후 팀원이 /chat에서 "손해율 트렌드 알려줘" 같은 질문 시 RAGFlow가 원문 검색 → 부서장 페르소나가 요약합니다.
