# 014. 부장 페르소나 에이전트 — 컨셉문서 반영 설계

> 원본: `C:\Users\Administrator\Documents\카카오톡 받은 파일\부장페르소나에이전트 컨셉문서.html`
> 대상: dept-agent(현 1차 MVP, Next.js + pi-agent-core + RAGFlow + Drizzle/SQLite)
> 이 문서는 "부장이 원하는 것"을 현재 아키텍처에 **어떻게 옮길 것인가**를 설계한다. 단위 구현 여부와 일정은 별도 실행 계획으로 분리한다.

---

## 0. 한 줄 정리

> "부장이 자리에 없어도 *부장이라면 어떻게 판단했을까*에 답하고,
> 그 판단이 쌓여 조직의 자산이 되는 Agent" — **컨센의 본질은 ① 판단지원(QnA), ② Human-in-the-loop 지식 축적, ③ 브리프/모니터링, ④ 코칭형 응답** 의 4개 축을, **지식 3단 레이어** 위에 올리는 것.

현재 dept-agent는 이 중 상당 부분(페르소나 QnA, RAG, 지식하네스+검토승인, 대시보드, 웹검색)을 이미 갖고 있다.
핵심 작업은 **"새로 짓기"가 아니라 "컨셉 문헌에 맞게 재구성 + 빈틈 메우기"** 이다.

## 2. 설계 원칙 (변경의 뼈대)

1. **Human-in-the-loop 불변**: 에이전트는 항상 "제안", 확정은 부장만. 컨셉의 지식 확인함을 dept-agent의 **improvement_candidates 큐**에 정렬시킨다(이미 존재). 신규·수정 지식은 `pending(대기중/미확인)` → `applied(확정)` 이 전부다.
2. **지식 3단 레이어를 프롬프트/DB에 명시적으로 반영** — 하나로 뭉뚱그리지 않고 출처 계층을 답변 근거에 태깅한다.
3. **스코프 있는 대화** — 카테고리 선택이 채팅 컨텍스트·스킬 선택·근거 참조를 제한.
4. **기존 하네스·RAG·웹검색·대시보드를 버리지 않고 확장** — 신규 모듈 최소화.

## 4. 기능별 설계

### 4.1 지식 3단 레이어 (컨셉 §03) — 답변 근거에 "레이어 태그"

**Layer 1 · 규정·매뉴얼** → 기존 **RAGFlow(RAG)** 가 담당. "이거 우리 업무 맞나요?"(직제·예산·RNR·위탁) 류는 RAG 우선. 회사·그룹 전략방향은 **별도 카테고리(RAG dataset)** 로 적재 → 전략나침반·전략연결태그의 소스.

**Layer 2 · 판단 기준·원칙** → 기존 **스킬(6개) + 지식하네스(prompt/skill/memory)** 가 담당. ★ IF-THEN + 상위 원칙 + 실패 사례 + 부서 사업계획(⑥) 포함.

**Layer 3 · 커뮤니케이션 스타일** → 응답스타일(§4.2)이 담당, 출력 톤만 조정(근거·판단은 Layer1/2 사용).

**지식공백 표기 (핵심)**
- personas.ts 에 지침 추가: *"시스템 데이터·RAG·내부 지식에 없는 영역(판례·분쟁조정례·업계 직관)은 숨기지 말고 `[지식 공백]` 라벨로 명시한다. 그 옆에 근거 없음을 밝히고, 있으면 '부장님께 확인 요청' 제안을 붙인다."*
- 답변 하단에 레이어별 출처 태그: `#[규정] #[판단기준] #[경험/공백]`.

### 4.2 응답 스타일: 코칭형(기본) / 결론형 (컨셉 §07)

- 최초 접속 시 선택 → `users.responseStyle` 저장 → 자동 적용, 언제든 헤더 토글.
- 프롬프트 주입(engine.ts): 코칭형=`되묻기 중심(이 관점 고려하셨어요?→예/아니오→분기→표준응답5단)` / 결론형=`되묻기 생략, 결론+핵심근거 선제시`.
- 미확정 항목 중 "세션마다 vs 프로필 고정" → **프로필 고정 + 언제든 변경**으로 결정(합리적 기본).

### 4.3 QnA 업무 카드 1~6 + 중분류 (컨셉 §05)

**6개 카드(claims-planning 기준) — 스킬과 1:1 정렬:**
| 카드 | 현재 스킬 |
|---|---|
| 1 지급보험금 관리(이상징후 5% 트리거) | 1-지급보험금건전성 |
| 2 보험금 시스템 관리 ★딥 | 3-업무자동화 |
| 3 고객편의성 제고(민원포함) ★딥 | 4-고객편의성 |
| 4 보험금품질적정성관리 | 2-보험금품질적정성 |
| 5 신상품 리스크 검토 ★딥 | 5-신상품리스크 |
| 6 부서 사업계획 및 KPI 관리 | **(신규 스킬 6 추가)** |
| 기타 | 0-기본처리 |

- 채팅 화면: 카드 선택 → 대화 시작 시 `conversations.categoryKey` 기록 → 해당 스킬을 컨텍스트에 고정(스코프 제한), 다른 스킬 라우팅 억제.
- 카드별 "중분류 탭"은 프롬프트의 업무 하위 절차 탭으로 표현(별도 UI 탭은 저우선).

### 4.4 전략 나침반 (컨셉 §05)

- **세션 배너**: 최초 1회 노출(세션 스토리지) → 🧭 아이콘으로 축소, 클릭 시 재전개. 문구는 `전략나침반_banner` 지식(부장이 요약)에서 로드, 월 1회 갱신 = 하네스 경로B 재사용.
- **전략연결 태그**: 답변마다 `⎋ 전략연결: 회사>그룹>부서` 인라인. 프롬프트에 지침 추가("각 답변 마지막에 1줄 전략연결 태그 부착").
- **마인드맵**: 홈 허브의 정적 3단(회사>그룹>부서) 구조, 각 노드는 Layer1(회사·그룹)/⑥(부서)에서 로드.

### 4.5 KPI 대시보드 재구성 (컨셉 §09)

- kpiCatalog를 **컨셉의 8개**로 교체:
  자동화율·디지털처리율·보험금처리기일·즉시지급률·서류없는청구이용율·지급지연율·품질점검시행율(목표13%)·오류율.
- 각 KPI에 `direction`(관리·대응 필요 방향)과 `linkedCategory`(연동 카드) 필드 추가.
- **2단계 흐름**: 배지 클릭 → ① 단계 `월별 추이 미니그래프(최근6개월+목표선+전년동월, 편차 시작 하이라이트, n개월째 지속)` → ② 단계 해당 카드 채팅 진입, 추이를 컨텍스트로(→ 판단 5단계 Step3 "개별 vs 구조적" 자동 분류).
- KPI 시계열 데이터는 dashboard 모듈의 시리즈 배열로 확장(설계서 013 정합).

### 4.6 업계동향 브리핑 (컨셉 §08)

- news.ts를 **실뉴스(외부 웹검색/뉴스) + 내부자료 보조**로 교체. 트리거: 해당 기간 유의미 이슈 있을 때만(없으면 브리핑 없음).
- 3단 출력: ①현황 ②인사이트(Layer2 적용) ③액션플랜 초안(편집 가능).
- **카드 연동**: 이슈 태그(시장→카드5, 지급기준→카드1, 제도·판례→카드4) → 클릭 시 컨텍스트로 채팅 진입.
- 기존 `/api/dashboard`의 news 부분과 `news.ts` 확장.

### 4.7 보고서 초안 (컨셉 §07)

- 채팅에 스코프(카테고리)별 "보고서로 정리해줘" 감지 → 현재 대화의 결론·근거·참고데이터를 구조화 마크다운 보고서로, 편집 가능한 상태로 출력.
- 업계동향 액션플랜과 동일 원칙 — **초안까지만, 확정은 부장**.

### 4.8 지식 축적: 경로 A/B + 지식 확인함 (컨셉 §04) ← **가장 중요한 확장**

- **경로A(직원)**: 답변에 `[지식 공백]` 라벨 → "부장님께 확인 요청" 버튼 → 대화 맥락(전체 turn)을 담아 `improvement_candidates` 생성 (`requestType=knowledge_gap`, `proposedByRole=user`, `sourceConversationId`). 상태=대기중(미확인).
- **경로B(부장)**: "이거 판단기준으로 저장해줘" → 에이전트가 IF-THEN 초안 생성 → 부장 즉시 확인 → 저장.
- **지식 확인함 UI**: 하네스 페이지(admin)의 검토 큐가 이미 승인/수정후승인/거절(사유)/보류 지원. 여기에 **직원발 요청(경로A)** 을 포함시켜 "누가 요청했는지·원본 질문·상태" 표시. 배치: 주간 "이번 주 지식공백 리포트" 생성(하네스 에피소드 압축 재사용).
- 스코프: 부장=관리자, 직원=user. 현재 Role 구조 재사용(부장을 admin으로 간주).

### 4.9 판단 로직 정식화 (컨셉 §06)

- personas.ts(claims-planning)에 추가:
  - **권한 범위** 표: ①②③④⑥=단독판단(결론까지), ⑤신상품=제안+근거까지·협의체(상품라운드테이블/상품전략위원회) 명시.
  - **판단 5단계** & **표준 응답 포맷 5단**(결론→근거→데이터출처→권한범위→확신도·다음액션).
  - **우선순위 사다리 A/B**, 원칙 라이브러리(6개) — 기존 스킬에 이미 일부 있으므로 통합 정리.
- 신상품 스킬(5)에 "제안+근거까지만, 균형있게" 명시(참고: 기존 실패 사례 반영).

## 6. 시연 우선순위 매핑 (컨셉 §10)

컨셉이 지정한 3개 딥 영역을 **하나의 흐름**으로:
1. **STEP1 · 카드5 신상품 리스크**(자동심사 확대 리스크/효과 시뮬, 가상 데이터) → 협의체 "제안+근거" 권한범위 시연
2. **STEP2 · 카드3 고객편의성**(민원예방·소비자보호) → 지식공백 확인요청 시연
3. **STEP3 · 카드2 시스템 관리**(룰 협의체 사전검토 자동화)
