# 009 — 지식 하네스 & 자기개선 (부서장 주도 개선)

> 작성일: 2026-09-09 · 상태: 설계 초안(Phase 1·2·3·4 구현 완료) · 범위: dept-agent 자기개선 기능 3요구 + Phase 4 부가
> 참고 설계 원천: prime-agent의 Continual Harness(프롬프트·메모리·스킬·서브에이전트 + refine 증거 기반 소규모 갱신)

## 0. 목표

부서장(관리자)이
1. 부서원 Q&A를 **압축(compaction)된 결론**으로 검토하고 평가·의견을 남기면,
   dept-agent가 그 내용을 **스킬/프롬프트/메모리**에 추가·수정한다.
2. 본인(부서장) 채팅 내용에서 필요한 지식을 **자동 선별**해 스킬·프롬프트·메모리에 적용한다.
3. 프롬프트·스킬·메모리 **모든 지식 정보를 UI에서 직접 보고 수정**한다.

핵심 설계 방향: **계층형 지식 저장소(Continual Knowledge Store) + 사람이 승인하는 리뷰 루프.**
자동 개선은 절대 조용히(무허가로) 적용하지 않는다. 모든 변경은 `후보(candidate) → 검토 → 적용/거절/수정` 흐름을 거치고,
적용된 항목은 **출처(provenance)·버전·롤백**을 가진다. 이것이 prime-agent의 "증거 기반, 소규모, 멱등" 원칙을 본 딴 것이다.

## 1. 문제 진단 (현재 상태)

| 항목 | 현재 | 문제 |
|---|---|---|
| 페르소나(시스템 프롬프트) | `personas.ts`에 하드코딩 문자열 | UI 수정 불가, 관리 불가 |
| 스킬 | `src/skills/<부서키>/*/SKILL.md` 파일 | 파일 편집은 코드 배포 필요, 변경 이력 없음 |
| 메모리 | 없음 | 대화 결론이 휘발, 재사용 안 됨 |
| 부서원 Q&A | `conversations`/`messages` 테이블에 축적 | 압축·요약·결론 추출 경로 없음 |
| 부서장 채팅 | 일반 채팅과 동일 | 학습 대상 선별·피드백 루프 없음 |
| 변경 추적 | 없음 | 누가 무슨 근거로 바꿨는지 알 수 없음 |

## 2. 아키텍처 개요 (계층형 지식 저장소)

```
[웹 UI(관리자)]  부서원 Q&A 검토 · 자동 후보 승인 · 프롬프트/스킬/메모리 편집 · 이력/그래프
        │
        ▼
[L3 지식 하네스 코어 (src/lib/harness/)]
   ├─ runtime  : buildSystemPromptWithHarness(personaKey)  // 베이스 + 활성 항목 병합
   ├─ store    : 프롬프트/스킬/메모리 CRUD + 버전기록(audit)
   ├─ compact  : 부서원 Q&A → 에피소드/결론 요약 (compact 모델)
   ├─ harvest  : 부서장 채팅 → 후보 지식 추출 (cheap 모델)
   ├─ apply    : 후보 승인 → 항목 생성/수정 + 출처 연결
   └─ graph    : 지식 node/edge (출처·충돌·연관)
        │
        ▼
[DB(SQLite + Drizzle)]  users/conversations/messages (기존)
   + knowledge_prompts / knowledge_skills / knowledge_memories   (활성 지식)
   + knowledge_versions                                        (이력·롤백)
   + episodes / improvement_candidates                          (압축 & 후보 큐)
   + knowledge_edges                                         (출처·충돌 그래프)
   + app_settings (기존, 하네스 토글·임계치)
```

병합 원칙(현재 `buildPersonaSystemPromptWithSkills` 확장):
```
최종 system = 베이스 페르소나(personas.ts, 읽기 전용)
            + 베이스 파일 스킬(src/skills, 읽기 전용)
            + DB 활성 knowledge_prompts (addendum/rule/role/correction)
            + DB 활성 knowledge_skills
            + DB 활성 knowledge_memories (신뢰도·히트수 정렬)
```
- 코드/파일은 "기본(베이스)"으로 두고, DB 항목이 "연속 개선층"으로 덧입힌다 → 소스 재배포 없이 즉시 반영.
- 편집 UI에서 베이스도 "복사해서 DB로 가져와 편집" 가능(origin='base_copied') — 레이어 구조는 유지.

## 3. 데이터 모델 (신규 테이블)

### 3.1 지식 항목 (활성 지식, 3종)
```sql
knowledge_prompts (
  id TEXT PK, persona_key TEXT NOT NULL,
  kind TEXT,              -- addendum(보강) | rule(행동규칙) | role(역할) | correction(오류정정)
  title TEXT, content TEXT NOT NULL,
  active INTEGER(1) DEFAULT 1,
  origin TEXT,           -- manual | auto | review | base_copied
  confidence REAL,       -- 자동 추출 신뢰도 0~1 (manual은 1)
  source_type TEXT, source_id TEXT,   -- 출처 (episode | conversation | message)
  order_idx INTEGER, hit_count INTEGER DEFAULT 0,
  created_at, updated_at
)
knowledge_skills (
  id TEXT PK, persona_key TEXT, name TEXT, description TEXT,
  content TEXT,          -- SKILL 본문 (frontmatter 별도 컬럼, 렌더 시 복원)
  active, origin, confidence, source_type, source_id, order_idx, hit_count, created_at, updated_at
)
knowledge_memories (
  id TEXT PK, persona_key TEXT,
  kind TEXT,            -- fact(사실) | preference(선호) | decision(결정) | lesson(교훈) | precedent(선례)
  content TEXT, tags TEXT(JSON),
  active, origin, confidence, hit_count,
  source_conversation_id, source_message_id,
  created_at, updated_at
)
```

### 3.2 버전·감사 (롤백 안전장치)
```sql
knowledge_versions (
  id TEXT PK, entry_type TEXT(prompt|skill|memory),
  entry_id TEXT, content_before TEXT, content_after TEXT,
  action TEXT(create|update|disable|activate|restore|delete),
  changed_by TEXT(admin id), created_at
)
```
어떤 항목이든 수정 시 이전 상태 스냅샷 저장 → 원클릭 롤백. 자동/수동 구분 없이 모두 감사.

### 3.3 압축·후보 (요구 1·2의 파이프라인)
```sql
episodes (                 -- 부서원 Q&A 압축 단위
  id TEXT PK, department_id TEXT,
  period_from, period_to,
  summary TEXT,          -- 묶음 요약(무엇을 물었는지)
  conclusion TEXT,       -- 결론/권고 본문(재사용 가치 있는 결론)
  source_ids TEXT(JSON), -- 포함된 message id 목록 → 원문 드릴다운
  token_count INTEGER, status TEXT(draft|ready|reviewed),
  created_at
)
improvement_candidates (   -- 적용 후보 큐 (요구1 승인=episode, 요구2=admin_chat)
  id TEXT PK, persona_key TEXT,
  source_kind TEXT(episode|admin_chat), source_id TEXT,
  summary TEXT,          -- 제안 근거(짧은 설명)
  action TEXT(create_skill|update_skill|create_prompt|update_prompt|create_memory|update_memory),
  target_title TEXT, proposed_content TEXT,
  confidence REAL,
  status TEXT(pending|approved|rejected|applied|edited),
  admin_note TEXT,      -- 부서장 의견/평가
  resolved_by TEXT, resolved_at, created_at
)
```

### 3.4 지식 그래프 (출처·충돌·연관 — 권장 그래프 관점)
```sql
knowledge_edges (
  id TEXT PK,
  from_type TEXT, from_id TEXT,   -- 지식 항목 | episode | conversation | skill | prompt
  to_type TEXT,   to_id TEXT,
  rel TEXT(derives|refutes|supports|related|source_of),
  created_at
)
```
- `episode →(source_of)→ memory/skill/prompt` : **출처 추적**(어느 Q&A에서 왔는지)
- `A →(refutes)→ B` : 새 지식이 기존 활성 지식과 모순될 때 **충돌 플래그** (무음 덮어쓰기 금지)
- `A →(supports)→ B` : 연관 지식 묶음 → 검토 화면에서 함께 표시

## 4. 요구사항별 흐름

### 4.1 요구 1 — 부서원 Q&A 압축 검토 → 스킬/프롬프트 반영

파이프라인:
```
부서원 대화 저장(기존) 
   → [compact] 같은 부서의 최근 유저 질문+에이전트 결론을 묶어 episodes 생성
       (compact 모델로 "질문 요약 + 결론 + 재사용 가능한 규칙?" 추출)
   → episodes 상태 ready, improvement_candidates pending 생성
   → 관리 화면 "자기개선 대시보드"에 노출 (부서별, 원문 드릴다운)
   → 부서장 평가: 
        [적용]                     → apply: proposed_content를 신규 스킬/프롬프트/메모리로 생성 (+출처 edge, 버전 기록)
        [적용 후 수정] → edited   → 편집 UI에서 다듬고 적용
        [거절]          → rejected (+admin_note 이유 저장, 재제안 방지)
   → 적용된 항목은 즉시 해당 부서 페르소나에 병합 (재배포 불필요)
```
- 트리거: 관리 화면 "압축 생성" 버튼(온디맨드) + N개 미검토 대화 초과 시 서버 주기 실행(예 10분 마다).
- 신규로 들어온 지식이 기존 활성 지식과 모순(`refutes`)이면 적용 차단 대신 **충돌 경고**를 검토 화면에 표시.

### 4.2 요구 2 — 부서장 채팅 자동 선별

```
부서장 채팅 완료(assistant 메시지 저장 후)
   → [harvest] cheap 모델이 해당 대화 메시지를 스캔해 고신뢰 지식 후보 추출:
       - 부서장이 에이전트 행동을 정정한 지점(오류 정정)
       - 반복 등장한 결정/선호(예: "다음 보고는 항상 전월 대비를 넣어줘")
       - 재사용 가치 있는 결론/선례
   → confidence >= 자동임계(예 0.8)만 improvement_candidates pending 생성
   → 부서장이 대시보드에서 한 번에 승인/거절 (완전 무음 자동 적용은 OFF 기본)
```
- 정확성 개선: "이 대화에서 배우기" 버튼(부서장이 명시적 요청)이 가장 신뢰도 높은 경로.
- 설정(`app_settings`)으로 `auto_apply_memory_low_confidence` 같은 정책 토글 지원. 기본은 **항상 사람 승인**.

### 4.3 요구 3 — 프롬프트/스킬/메모리 편집 UI

관리 화면 "지식·자기개선" 탭 추가. 하위 뷰:
1. **자기개선 대시보드** — episodes 검토 큐 + 자동 후보 큐 (부서 필터, 충돌 배지)
2. **프롬프트 편집** — 부서별 knowledge_prompts 목록/추가/수정/비활성; 베이스 페르소나 읽기 전용 + "복사해 편집"
3. **스킬 편집** — knowledge_skills 목록/추가/수정 (이름·설명·본문 textarea, frontmatter 도움말); 베이스 파일 스킬도 병합 미리보기
4. **메모리 관리** — knowledge_memories 목록 (종류·태그·신뢰도·히트수 필터), 추가/수정/비활성
5. **변경 이력** — knowledge_versions (항목 클릭 시 content diff + "이 버전으로 복원")
6. **(선택) 지식 그래프** — node/edge 시각화(출처·충돌·연관) — 전용 그래프 DB 없이 SQLite 인접리스트로 렌더

API (전부 `requireAdmin`):
```
GET    /api/admin/harness?departmentId=&type=prompt|skill|memory
POST   /api/admin/harness                 (생성)
PATCH  /api/admin/harness/[id]           (수정/비활성/활성)
DELETE /api/admin/harness/[id]           (소프트 disable + 버전 기록)
POST   /api/admin/harness/[id]/restore   (특정 버전 복원)
GET    /api/admin/episodes?departmentId=   (압축 큐)
POST   /api/admin/episodes/generate        (즉시 압축)
PATCH  /api/admin/candidates/[id]         (approve|reject|edit → apply)
POST   /api/admin/harvest?conversationId= (부서장 채팅 자동 선별 / "이 대화에서 배우기")
GET    /api/admin/harness/graph          (node/edge 목록)
```

## 6. 권장 사항 — 그래프적 데이터 관리 & 기타 아이디어

### 6.1 그래프적 관리: 어떤 수준까지?

- **MVP 확정: 관계형 + 출처 그래프.** SQLite에 `knowledge_edges`(node/edge 인접리스트)를 두고
  "출처 추적 · 충돌 감지 · 연관 묶음"을 충족. 지식 규모가 수백~수천 이라면 이 정도면 충분하고
  운영 복잡도가 전혀 늘지 않는다.
- **다음 단계(부서 늘고 지식 많아질 때):**
  - **벡터 검색 + 그래프 하이브리드 RAG**: 메모리/스킬이 많아지면 SQLite에 벡터 임베딩 컬럼(예 `text-embedding`)을 추가하거나,
    RAGFlow/외부 벡터 저장소에 지식 인덱스를 만들어 검색 시 관련 지식을 프롬프트에 주입.
  - **전용 그래프/문서 DB**: Neo4j, Postgres+Apache AGE, 또는 Memgraph. 멀티테넌트·대규모·깊은 추론(몇 단계 관계 탐색)이 필요해질 때만.
    지금 단계에선 과잉(over-engineering)이다.
- **판단 기준**: 지식 수 < 수천 · 편집/추적이 주 용도 → 관계형+인접리스트. 
  관계 탐색 깊이/질이 제품 차별화 지점이 되면 그래프 DB 전환 검토.
- **프로바이넌스가 곧 그래프의 핵심 가치**: "이 규칙이 왜 생겼나?"를 클릭 한 번으로 episode → 대화 원문까지 추적 가능하게 하는 것이
  관리자가 신뢰하고 수정하는 전제 조건이다.

### 6.2 기타 추천 아이디어

1. **피드백 메트릭스 기반 우선순위**: 각 지식 항목에 hit_count(실제 프롬프트에 주입·사용된 횟수), 그리고 대화 말미
   유용성 평가(👍/👎)를 쌓아, 자동 개선·정리가 "가장 많이 쓰이는/안 쓰이는" 지식을 우선 처리한다.
2. **버전 & 롤백 기본 내장**: 어떤 변경도 소프트 disable + 버전 스냅샵. 생성 후 문제 발견 시 원클릭 복원.
3. **Dry-run / 자동평가**: 새 스킬/프롬프트 적용 전에 기존 과거 질문 샘플을 돌려
   기존 응답 대비 개선 여부를 점수화(prime-agent의 prompt-evaluator와 유사)하고, 퇴행이 우려되면 경고.
4. **A/B(선택)**: 특정 규칙을 일부 부서/비율로만 적용해 효과 검증.
5. **충돌 = 차단이 아닌 경고**: 무음 덮어쓰기 금지. 모순되는 새 지식은 적용 전 배지로 표시해 부서장이 판단.
6. **가드레일**: 
   - 자동 개선 기본값 = "후보 제안까지만, 적용은 사람 승인".
   - 절대 자동 삭제 금지(disable만). 
   - 부서장(관리자) 권한만 편집 가능, 구성원은 읽기 전용.
7. **임포트/익스포트**: 지식 저장소 전체를 JSON/YAML로 백업·복원·시드. 부서 간 지식 공유(템플릿화)에 활용.
