# f009. 토론방 (Debate Room)

> 상태: 구현 완료(v2 포함) · 검증 `npx tsc --noEmit` exit 0 + `npx vitest run` 55 files / 354 tests passed
> 계획서: `docs/plans/019-debate-room.md`

## 목적

복잡한 기획·의사결정 안건을 사람이 프롬프트로 정리하는 대신, **서로 다른 페르소나 에이전트들이 실시간 메신저 형태로 난상토론**하게 하고 사람은 관전만 한다. 토론이 끝나면 **최종 결론 에이전트**가 합의·쟁점·리스크·권고 액션을 정리한 **최종 보고서(MD)** 를 작성한다.

- 기대 효과: 기획안의 허점과 기대 효과를 입체적으로 파악, 소요 시간은 설정한 토론 시간으로 통제.
- 산출물: `DATA_DIR/debates/<sessionId>/report.md` (화면에서는 MD 뷰어로 표시, 다운로드 가능)

## 사용법

1. 사이드바 **토론방**(`/debate`) → 안건(제목) 입력
   - **기획안 파일 업로드**: `📎 기획안 파일 올리기` 또는 드래그&드롭 → 본문 텍스트가 자동으로 채워진다 (txt·md·csv·json·html·docx 지원, 10MB 이하). 올린 파일명은 세션에 기록되어 목록/관전 화면에 표시된다.
2. **참가자** 선택(기본 프리셋 5명, 옵저버/커스텀 포함) + **토론 시간** 선택(1/3/5/10/15분)
   - `⚙ 페르소나 관리 · 편집`에서 기본 페르소나도 **역할·입장·전문영역·목표·양보선·말투·색·추가 지침**을 수정할 수 있고, `기본값으로 되돌리기`로 복원한다.
3. **토론 시작** → 관전 화면(`/debate/<id>`)으로 이동, 백그라운드에서 토론이 진행된다
4. 관전: 말풍선 타임라인 · 남은 시간 · 라운드/발언 수 · 현재 발언자 링 · 타이핑 인디케이터 · "새 발언 N개" 점프
5. 시간이 끝나거나 **중단하고 결론**을 누르면 최종 결론 에이전트가 보고서를 작성 → **최종 보고서** 탭(MD 뷰어) + `MD 다운로드`
6. 지난 토론은 토론방 허브의 목록에서 다시 열람
7. **다음 토론으로 이어가기**: 관전 화면 상단은 항상 화면에 고정되어 `← 토론 목록 · 새 토론`/`↻ 같은 안건으로 다시 토론` 버튼이 보인다. 토론이 끝나면 하단에도 `＋ 새 토론 시작` · `↻ 같은 안건으로 다시 토론` · `최종 보고서 보기` 버튼이 나타난다.
   - `새 토론 시작` → 허브(작성 폼 + 지난 토론 목록)로 이동
   - `같은 안건으로 다시 토론` → 제목·기획안·첨부파일·참가자·시간을 그대로 복사해 **새 세션을 만들어 즉시 시작**(기존 결과는 보존)

## 토론 엔진 규칙

- **발언 순서**: 옵저버(금감원 등)를 라운드 첫 발언으로 두고, 이후 등록 순서 라운드 로빈. 전원 1회 발언 = 1라운드.
- **라운드 단계**: 1R 입장 개진 → 2R 반박·공방 → 3R 조건·대안 → 4R+ 쟁점 좁히기. 라운드마다 지침이 달라지고, 직전 발언자 1명을 지목해 반응하도록 요구한다(`rounds.ts`).
- **말투 다양화**(`style.ts`): 마무리 방식을 6종(`질문/단정/조건 제시/사실 지적/대안 제안/감정 토로`) 순환 배정하고, 문장 리듬도 턴마다 교체한다. 직전 3개 발언의 끝맺음을 프롬프트에 보여주며 "비슷한 마무리 금지". `"~할 의향이 있습니까?"` 같은 상투적 질문은 금지 규칙으로 막는다.
- **발언 출력 = JSON**: 모델은 `{ speech, emotion, satisfaction(0~100), stance, innerThought }` 를 한 번에 낸다(추가 호출 없음). 잘린 JSON 은 관용 파서로 복원하고, 허용 목록 밖 값은 비우며, JSON 이 아니면 발언문만 저장하고 상태는 비운다 — 파이프라인은 계속된다.
- **프롬프트**: 페르소나 프로필(역할·입장·전문영역·목표·양보선) + 안건·기획안 + 라운드 단계 지침 + 남은 시간 + 최근 18발언. 반복 금지·새 근거 1개 이상·미확인 수치 금지 규칙을 공통 주입.
- **종료 조건**: 설정 시간 경과 · 사용자 중단(`stopped`) · 최대 발언 수(80) · 연속 모델 오류 3회.
- **진행 갱신 안전장치**: 진행 상황 갱신은 `status='running'` 일 때만 반영 → 중단 요청을 덮어쓰지 않는다(`updateProgressIfRunning`).
- **결론**: 전체 로그 → 합성 JSON(`verdict, summary, agreements, conditions, disputes, risks, actions, positions(stance), openQuestions, decisionBasis`) → 결정적 MD 템플릿. 라운드별 흐름은 LLM 이 아니라 **발언 로그에서 결정적으로** 생성한다(사실 왜곡 방지). 합성 실패 시 로그 기반 fallback. 결론 메시지도 타임라인에 남긴다.
- **실시간 전달**: 관전 화면이 `GET /api/debate/<id>/stream?since=<seq>` 를 1.2초(탭 비활성 시 5초) 간격으로 폴링. 페이지 새로고침·재접속에 강하다.
- **중복 방지**: ① 초기 로드가 끝나기 전에는 폴링하지 않고(`readyRef`), ② 메시지 병합은 `merge.ts` 의 `mergeIncoming` 으로 **id/seq 기준 중복 제거**(초기 로드와 첫 폴링이 겹쳐 같은 발언이 두 번 append 되어 "two children with the same key" 오류가 나던 문제 해결), ③ 렌더 단계에서도 id 기준 한 번 더 방어(`DebateStage`), ④ `POST /api/debate/[id]/start` 는 프로세스 내 in-flight 가드로 **실행 루프가 두 번 돌지 않게** 한다.

## 페르소나별 모델 설정

관리자 **설정 → 페르소나별 모델**에서 페르소나마다 다른 LLM을 지정할 수 있다.

- 저장 위치: `app_settings` 키 `debate_persona_models` = `{ "<personaKey>": { model, gateway } }`
- 해석 순서: **페르소나별 지정 → "간단 응답(simple)" 용도 모델**
- 미지정(빈 값)은 지정 해제 → 기본값 사용
- 화면에는 페르소나별 `적용 중` 값과 `(저장 대기)` 표시가 나온다
- 모델 목록은 같은 화면의 **용도별 LLM 모델**에서 게이트웨이를 고른 뒤 "목록 불러오기"로 채운다

## 참가자 감정 · 속마음 (별도 섹션)

대화창(말풍선)에는 **발언만** 표시하고, 화면 오른쪽 **`참가자 감정 · 속마음`** 섹션에 참가자별로 계속 갱신해 보여준다(`EmotionPanel.tsx`).

| 항목 | 내용 |
|---|---|
| 감정 | 🌤기대 · 😌만족 · 😐중립 · ⚠️우려 · 😤불만 · 🧱단호 배지 |
| 만족도 | 0~100 게이지 + 숫자 + 스파크라인(턴별 변화, 색상으로 악화/개선) |
| 입장 | 찬성 / 조건부 / 반대 / 유보 배지 |
| 속마음 | 최신 한 줄 인용 + `이전 속마음 보기`(턴별 기록 최대 6개) |

설계 선택: 발언과 상태를 **한 번의 LLM 호출로 함께** 받는다(별도 평가 호출 없음). 감정·만족도는 LLM 의 자기보고 추정치이며, 사람의 실제 감정 측정값이 아니다.

**레이아웃**: 컨테이너는 `max-w-[1440px]` 로 넓게 쓰고, 라이브/보고서 탭 모두 `xl:grid-cols-[minmax(0,1fr)_320px]` 2단이며, 좌(토론창·보고서)와 우(감정 섹션)의 높이를 **동일하게**(`h-[68vh] min-h-[420px] lg:h-[72vh] lg:min-h-[560px]`) 맞추고 **각자 내부 스크롤**(`overflow-y-auto` + `.debate-scroll` 얇은 스크롤바)을 둔다. 감정 섹션은 헤더 고정(`shrink-0`) + 목록만 `flex-1 min-h-0 overflow-y-auto`. 모바일은 세로로 쌓인다.

## 최종 보고서 구성

1. 결론(판정 + 요약) · 2. 라운드별 흐름 · 3. 합의된 사항 · 4. 조건부 합의 · 5. 쟁점(찬성/반대 표) · 6. 참가자별 입장(찬성/반대/조건부 표) · 7. 남은 리스크·미해결 · 8. 미해결 질문 · 9. 의사결정 근거 · 10. 권고 액션(담당/기한 표) · **부록 A. 참가자 감정·속마음**(최종 입장 / 만족도 변화 `30 → 45 → 55` / 감정 흐름 / 마지막 속마음 표)

> 발언 로그는 보고서에 넣지 않는다 — 전체 대화는 관전 탭(타임라인)에서 언제든 볼 수 있으므로 보고서 중복을 피한다.

**표시 방식**: 저장된 MD 를 그대로 던져주지 않고 **MD 뷰어(렌더링)** 로 보여준다.
- 보고서 탭은 기본이 `뷰어`(HTML 렌더링)이고, 필요할 때 `MD 원문` 토글과 `MD 파일 저장`(다운로드)을 쓴다.
- `MarkdownViewer` 가 표(table) 렌더링을 지원한다(globals.css 스타일 포함).
- 저장된 원문에 이스케이프된 개행(`\n` 두 글자)이 섞여 있어도 뷰어가 문단으로 복원한다.
- 다운로드 응답은 `Content-Disposition: attachment; filename="debate-<id>.md"; filename*=UTF-8''...` 로 **브라우저가 원문을 탭에 그대로 표시하지 않게** 한다.

**보고서로 가는 동선**
- 토론이 끝나면(완료/중단) 화면이 **자동으로 `최종 보고서` 탭**으로 전환되어 렌더링된 보고서를 먼저 보여준다(사용자가 탭을 직접 고른 경우는 유지).
- 지난 토론 목록의 `보고서 보기` 버튼 → `/debate/<id>?tab=report` 로 바로 진입.

## 확정 기본값

- 토론 시간: 기본 3분, 선택 60/180/300/600/900초
- 최대 발언 수 상한 80, 발언 간 지연 0.9초
- 참가자 2~8명(결론 에이전트 제외), 초과분/미존재 key 는 무시

## 지원 파일 형식

| 형식 | 처리 |
|---|---|
| txt · md · csv · tsv · json · html · xml · yaml | UTF-8 본문 그대로(최대 60,000자) |
| docx | ZIP 컨테이너에서 `word/document.xml` 을 꺼내 텍스트만 추출(외부 의존성 없이 `node:zlib`) |
| pdf · doc · pptx 등 | 미지원 → 안내 메시지(본문을 붙여넣도록 유도) |

## 향후 과제

- SSE 전환(폴링 → 스트리밍), 진행 중 개입(관전자 질문 주입), 발언권 배분 LLM 사회자
- pdf/pptx 본문 추출(현재는 docx 까지)
- 페르소나 프로필의 팀 공유(현재는 생성자 기준 저장)
- 토론 종료 결과를 지식하네스 후보(`improvement_candidates`)로 승격
- 토론 요약을 부서장 페르소나 메모리로 적재
