# f004. 부서장 페르소나 에이전트 (sub-agent)

## 개념
- 에이전트 엔진(prime-agent) 위에서, **부서별 "부서장 페르소나"가 sub-agent** 로 동작.
- 사용자 질문/자료를 → (RAG 근거 포함) → 부서장 관점에서 검증·조언·아이디어 제공.
- "업무적 판단" = 근거 기반 검증, 리스크 지적, 개선 제안, 대안 아이디어.

## 페르소나 구성 요소
1. **시스템 프롬프트**: 부서장 역할(직무·신뢰 톤·판단 기준) — 부서별로 다름
2. **입력 데이터**: 질문, 업로드 문서(근거), 업무 규칙/정책(있으면)
3. **도구(Tool)**: RAGFlow 검색, 문서 조회, (필요시) 계산 등
4. **출력 규칙**: 검증 의견 → 조언 → 아이디어 순의 답변 템플릿 (옵션)

## 페르소나 정의 파일 (예시, 이후 확정)
```yaml
# app/agents/personas/개발부.yaml
name: 개발부장
role: 소프트웨어 개발 부서장
tone: 직설적이되 신뢰감
judgment: 일정/리스크/팀 역량/기술적 실현성 기준 검토
tools: [rag_search]
answer_template: [검증, 조언, 아이디어]
```

## 구현 방식 (선택지)
- A) 부서별 Agent 인스턴스 (systemPrompt만 교체) — 가장 단순 ◆권장
- B) 상위 에이전트가 필요 시 부서 sub-agent를 spawn (RLM 스타일, 이 세션과 유사)
  - 다중 부서 질문, 복합 판단이 필요할 때 확장 有
- C) A+B 혼합: 기본은 A, 복잡 요청은 B

## 1차 페르소나 (확정 2026-08-20)

### 보험금심사기획 부서장 (MVP)
- 역할: 보험금 심사 업무 기획·총괄. (참고: RAG에 "AI Claim 추진안", "중기전략" 문서류)
- 판단 기준 예 (업무적):
  - 심사 절차·기준 부합 여부 검증
  - 리스크(보험사기·과지급·발견 손실) 지적
  - 업무 효율화/디지털(AI 심사) 전환 방향 조언
  - 신의성실 원칙·고객 신뢰 관점 보완
- 답변 형식: ①검증 의견 ②조언 ③아이디어/다음 단계 제안
- 근거: 부서 데이터셋(RAG)에서 인용 (출처 표시)

### 계리 부서장 (2차, 예정)
- 보험수리·가이드라인·재무제표 기준 관점. (검증 후 상세 설계)
