# f007. 대시보드→채팅 주제 전달 · 기본 지식 편집 · 메뉴 안정성 · 적용 후보 큐 개선

## 개요
사용자 피드백 3건(메뉴 이동, 기본 지식 편집, 대시보드→채팅 주제/부서 유실)과
적용 후보 큐의 수명·중복 관리 요청을 반영한다.

## 1. 대시보드→채팅: 주제 자동 채움 + 부서 전달 (f003 대시보드, f001 채팅)
- 대시보드 질문 카드(`QBtn`)가 `/chat?q=<주제>&dept=<부서>` 로 이동 → 채팅 페이지가 `?q` 를 읽어
  **질문 입력란에 주제를 자동 채우고 포커스**한다(`setInput(q)` + `inputRef.focus()`).
  `?dept` 가 있으면 관리자 `activeDepartmentId` 도 반영.
- 중복 채움 방지: `consumed.current.q` ref로 탭 재진입·재렌더 시 한 번만 채움.
- `makeConversation()` 오류 메시지 개선: 서버에서 돌아온 실제 오류(예: "부서 정보가 없습니다.")
  를 노출하고, 범용 "부서를 선택해 주세요" 로 덮어쓰지 않는다.
- 메뉴 버튼에 `cursor-pointer` 추가 — 이동이 "안 되는" 인상을 방지(체감 개선).
- 파일: `app/src/app/(app)/chat/page.tsx`, `app/src/app/(app)/layout.tsx`

## 2. 기본 지식(base) 편집 — 사본(base_copied) 오버레이
- 기본 지식은 코드 내장(읽기 전용)이며 백엔드/프론트 코드를 바꾸지 않고는 수정할 수 없다.
- "기본 지식도 편집" 요구 해결: 기본 항목을 **DB 학습 사본(base_copied)으로 복사**하면,
  해당 사본이 유효 편집본이 되어 자유롭게 수정·삭제·이력 관리된다. 기본 파일은 그대로 유지.
- HarnessPanel의 기본 항목에 「이 항목 편집 (사본 만들기)」 버튼 추가 →
  `POST /api/admin/harness?type=…` 로 `{origin:"base_copied", sourceType:"base", sourceId:<baseRef>}` 생성.
- `listEffective` (inventory.ts)에서 해당 기본 항목은 사본(learned)으로 덮어져 유효 목록에 **숨겨진다**.
  기본 스킬 id는 이름 기반(`base:skill:<persona>:<name>`)으로 안정화해 연결 신뢰도를 높임.
- 파일: `app/src/lib/harness/inventory.ts`, `app/src/app/(app)/admin/HarnessPanel.tsx`

## 3. 적용(apply) 후보 큐 — 수명 정리 + 수정/교체 선택 (하네스 개선)
- **1주일 수명**: 어떤 선택(적용/거절)도 없이 1주일 지난 미결정(pending) 후보는 큐에서 자동 정리
  (`pruneStaleCandidates`, GET/POST `/api/admin/candidates` 진입 시 지연 정리).
- **연관 감지**: 각 대기 후보에 대해 연관/유사 기존 지식(프롬프트·스킬·메모리)을 실시간 계산해
  `related` 목록으로 반환 (`findRelatedItems`).
- **신규/수정/교체 선택**: 후보에 연관 항목이 있으면 관리자가 라디오 버튼으로
  「신규 생성 / 기존 수정 / 기존 교체」를 고르고, 대상 항목을 선택할 수 있다.
  - `modify`: 기존 항목 내용을 수정(같은 id, 변경 이력 유지)
  - `replace`: 기존 항목 비활성화 + 후보 내용으로 새 항목 생성
  - `applyCandidate`가 `mode`/`targetType`/`targetId` 오버라이드를 지원
- 파일: `app/src/lib/harness/review.ts`, `app/src/app/api/admin/candidates/route.ts`,
  `app/src/app/(app)/admin/ReviewQueue.tsx`
- 테스트: `app/src/tests/harness-review.test.ts`(증가분), `app/src/tests/candidates-route.test.ts`
