# f001. 인증·세션 관리 레이어 (확정 2026-08-20)

## 목적
- 외부 웹에서 **@shinhan.com 도메인 이메일**로 회원가입 → 로그인 → 세션 유지 → 부서 권한.

## 흐름
1. **회원가입** (확정: 관리자 승인형)
   - 이메일: 도메인 화이트리스트 검사 (환경변수 `ALLOWED_EMAIL_DOMAINS` 예: `shinhan.com,shinhanlife.co.kr`)
   - 필수: 이름, 소속 부서 선택 (1차: 보험금심사기획 / 2차: 계리 추가)
   - 비밀번호: bcrypt 해시
   - **첫 가입자(사용자 0명일 때)는 자동으로 관리자+활성화**
   - 그 외 가입자는 `status=pending` → 관리자 승인 전까지 로그인 불가
2. **로그인**: 이메일+비밀번호 → 세션 발급
3. **세션**: 서버 세션 테이블(불투명 토큰) + httpOnly 쿠키. 만료·로그아웃·추방 가능
4. **미들웨어(가드)**: 모든 API에서 세션 검증, 요청자 부서/역할 주입

## API (예)
- `POST /api/auth/register` {email, name, password, departmentId}
- `POST /api/auth/login` → Set-Cookie(세션)
- `POST /api/auth/logout`
- `GET /api/auth/me` → {id, name, department}
- `GET /api/departments` → 가입 시 부서 목록

## 데이터
- `User(id, email UNIQUE, name, password_hash, role, department_id, is_active, created_at)`
- `Session(id, user_id, token_hash, expires_at, created_at)`

## 보안
- httpsOnly+SameSite 쿠키, bcrypt, 로그인 레이트리밋
- 부서 권한은 모든 RAG 검색 경로에서 서버측 재검증 (클라 신뢰 금지)
