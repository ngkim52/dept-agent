## 1. 드라이런 평가 — LLM-as-judge (부서장 에이전트 Q&A)
기존의 단순 "내용 유무" 스코어러(`assess.ts`)를 넘어, 업무별 질문을 부서장 에이전트에 실제로 던지고
LLM이 답변 품질을 5개 차원으로 판정하는 진짜 평가로 교체했습니다.

- **업무별 질문 은행** (`src/lib/harness/dryrun.ts`): `DRYRUN_CATEGORIES`
  - `claims` 보험금심사 · `ops` 배치자동화 · `report` 보고·규제 · `team` 부서운영
  - 각 질문에 `intent`(검증 의도) 명시 — 예) "과거 종료된 회의 이벤트를 현재로 오인하는지"
- **평가 파이프라인** (`runDryrunEvaluation`, `ask`/`call` 주입 가능 → 테스트 결정적·빠름)
  1. `retrieveDepartmentChunks` + `runPersonaAgent`로 부서장 에이전트 답변 생성
  2. LLM-as-judge가 5개 차원 판정: `relevance`(관련성) · `groundedness`(근거/출처) ·
     `knowledge_gap`(지식 공백·헛점) · `temporal`(시점 정합성 — 과거 회의록 종료 이벤트를 현재로 오인 시 감점) · `completeness`(완결성)
  3. `totalScore`(평균) + `findings`(info/warn/risk 수준 지적) + `latencyMs` 반환
  4. verdict: `위험`(risk 지적 or temporal<50) / `양호`(≥75) / `보완필요`
- **라우트**: `GET /api/admin/dryrun/questions`, `POST /api/admin/dryrun/evaluate`
- **UI**: `DryRunPanel.tsx` → 부서 선택 → 업무별 질문 선택 → 「평가 실행」 → 5차원 점수·지적·답변·소요시간 표시
  (백업·평가 탭 `BackupAssessPanel`에 통합)

## 2. 후보 큐 연관 판단 — LLM이 진짜 유사 항목만 선택
- `findRelatedByLLM`(`review.ts`)가 페르소나 활성 지식(메모리·규칙·스킬)을 LLM에 주고
  진짜로 의미가 겹치거나 충돌하는 항목만 반환("무관·단어 흡사 제외"). 실패 시 휴리스틱 폴백.
- GET `/api/admin/candidates`가 LLM 판정 결과를 `related`로 부착 (`DRYRUN_JUDGE_DISABLED=1`로 테스트는 결정적·오프라인).
- **UI 비교**: `modify`/`replace` 선택 시 **기존 지식 내용**과 **새 제안 내용**을 나란히(side-by-side) 표시해 비교.

## 3. 에피소드 — 설계 의도 명확화 + 결론 지식 저장
- **설계 의도**: 에피소드는 QA 대화 → (압축) → 에피소드 → (결론 확정) → **지식(메모리)** 파이프라인의 중간 산출물.
  `ready` 상태는 "결론 확정 가능/검토 대상"을 뜻하며, 그 자체가 페르소나에 바로 주입되지는 않습니다(부서장 승인이 관문).
- `publishEpisodeConclusion`(`review.ts`)이 에피소드 결론을 `origin:"episode"` 메모리로 저장.
- `getEpisodeDetail`이 파생 후보 상태까지 함께 반환(영향 추적).
- 라우트 `POST /api/admin/episodes/publish`, 에피소드 탭에 「결론을 지식(메모리)으로 저장」 버튼 + 안내문.

## 4. 지식 그래프 — LLM 관계 판단·저장·표시
- `knowledgeGraph.ts`: `collectGraphItems`(활성 지식 수집), LLM이 의미상 연관 쌍만 제안
  (`derives`/`refutes`/`supports`/`related`/`source_of`), 무효 id·자기참조 제외, 기존 연결 중복 제거 후 저장.
- 라우트 `POST /api/admin/harness/graph/build`.
- **UI**: 그래프 탭에 「＋ LLM로 관계 자동 구성」 버튼(부서 연동) + 관계종류 범례(source_of/related/supports/refutes/derives).
