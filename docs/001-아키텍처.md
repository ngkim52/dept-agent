## 1. 전체 시스템 구조 (레이어 구조도)

```
┌────────────────────────────────────────────────────────────────────────┐
│ L1  [웹 브라우저]  로그인 / 질문 / 자료 업로드 / 답변(SSE 스트리밍)      │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ HTTPS (Next.js Route Handler)
┌───────────────────────────────────▼────────────────────────────────────┐
│ L2  [웹 앱 서버 = Next.js 16 (App Router, TS) — 단일 Docker 이미지]      │
│                                                                        │
│  ┌─────────────────────┐   ┌───────────────────────────────────────┐  │
│  │ 인증/세션 레이어       │   │ 비즈니스 API (Route Handlers)          │  │

│  │  me                  │   │  departments, admin/users            │  │
│  │  (bcrypt+쿠키세션)    │   │                                       │  │
│  └─────────────────────┘   └──────────────────┬────────────────────┘  │
│                                                │                      │
│  ┌─────────────────────────────────────────────▼────────────────────┐ │
│  │ L3  에이전트 엔진 (src/lib/agent/)                                │ │
│  │  ├ engine.ts      상위 PI 에이전트 + 부서 서브에이전트 위임 툴       │ │
│  │  ├ llm.ts         pi-ai LiteLLM 프로바이더 등록                    │ │
│  │  └ personas.ts    부서장 페르소나 (보험금심사기획/계리)              │ │
│  └─────────────────────────────────────┬────────────────────────────┘ │
└─────────────────────────────────────────┬──────────────────────────────┘
                                          │ 추적/네트워크
        ┌─────────────────────────────────┼───────────────────────────┐
        ▼                                 ▼                           ▼
  ┌──────────────┐                 ┌──────────────┐           ┌──────────────┐
  │ DB(SQLite)   │                 │ RAGFlow(별도)│           │ LiteLLM(별도)│
  │ Drizzle ORM  │                 │ 부서 데이터셋  │           │ 게이트웨이     │
  │ 사용자/부서/   │                 │ retrieval API│           │ OpenAI 호환    │
```

- **L1**: 클라이언트 (Vue 없이 Next 서버 렌더 페이지 + fetch SSE)
- **L2**: Next.js 서버 — API 라우트가 인증·권한·대화·문서 처리
- **L3**: 에이전트 엔진 — **pi-agent-core `Agent` 기반** (상위 에이전트 + 서브에이전트)
- **외부**: DB(SQLite), RAGFlow(부서 데이터셋 검색), LiteLLM(LLM 게이트웨이)

## 2. 에이전트 엔진 상세 (v0.2 — 실제 구현)

### 2.1 핵심 객체 (engine.ts)

실행 시 `@earendil-works/pi-ai`의 `Models` 인스턴스 + custom `LiteLLM` provider를 만들고,
피어소나에 해당하는 **pi-agent-core `Agent`** 를 1개 생성한다.

```
runPersonaAgent(persona, userMessage, history, ragChunks, cb)
   │
   ├─ getLlmModel()                              // pi-ai Models + LiteLLM provider
   │     models.streamSimple.bind(models)        // streamFn
   │
   ├─ [L3-1] 상위 PI 에이전트 (parent Agent)
   │     systemPrompt  = persona.systemPrompt    // 부서장 페르소나
   │     model         = litellm/deepseek-v4-flash
   │     tools         = [ delegate ]            // 부서 서브에이전트 위임 툴
   │     messages      = toPiHistory(history)    // DB 히스토리 → pi-ai 메시지
   │
   ├─ [L3-2] 서브에이전트 (child Agent, delegate 툴 실행 시 임시 생성)
   │     systemPrompt  = 하위 부서 페르소나 (claims-planning | actuarial)
   │     tools         = []                       // 하위는 툴 없이 단일 질문 처리
   │     실행: sub.prompt(question) → 결과 텍스트 반환
   │
   └─ 스트리밍: agent.subscribe(message_update)
          assistantMessageEvent.type === "text_delta" → cb.onTextDelta(delta)
```

- 상위 에이전트가 스스로 `delegate` 툴을 호출하면, 하위 서브에이전트가 **새 Agent 인스턴스로 스폰**된다.
- 하위 에이전트 결과는 `AgentToolResult.content` 로 상위 에이전트에게 전달돼 최종 답변에 포함된다.
- 라이브 확인: 상위 PI 에이전트 → delegate 툴 → 계리 부서장 서브에이전트가 실제 LiteLLM으로 답변 생성 (SSE 스트리밍 + DB 저장 검증 완료).

### 2.2 툴 계약 (delegate)

```ts
// makeSubAgentDelegateTool(streamFn, model)
parameters = Type.Object({
  department: Type.Union([Type.Literal("claims-planning"), Type.Literal("actuarial")]),
  question:   Type.String(),
})
// 반환
result = { content: [{ type: "text", text }], details: { department } }
```

- 부서 매핑: `claims-planning`(보험금심사기획) / `actuarial`(계리)
- 상위가 보내는 질문에 따라 툴이 어느 서브에이전트를 스폰할지 결정.

## 3. 질문-응답 흐름 (SSE, v0.2 라이브 구현)

```
POST /api/chat/stream   { conversationId, message }
  → requireUser (쿠키 세션)
  → 대화 조회 (소속 부서 확인)
  → persona = getPersona(department.personaKey)
  → 이전 메시지 로드 (history)
  → 사용자 메시지 DB 저장
  → retrieveDepartmentChunks(질문, 부서_dataset_id)   // RAGFlow 검색
  → SSE 스트림 시작:
        event: start        { conversationId }
        event: citations    { chunks: [...] }            // 유사도 상위 (기본 5, ≥0.2)
        event: text_delta   { delta }                    // 실시간 토큰
        event: done         { messageId, content }
        event: error        { error }                    // 실패 시
  → 어시스턴트 메시지 DB 저장 (content + citations)
  → 최초 대화면 제목 = 질문 앞 30자
```

- **RAG**: 검색 결과는 `<<<RAG_CONTEXT>>>` 블록으로 상위 에이전트 프롬프트에 삽입.
- **응답 저장**: `messages` 테이블에 user/assistant 양쪽 저장.

## 4. 레이어별 기능 요약

| 레이어 | 구성 요소 | 주요 기능 |
|---|---|---|
| **L1 웹 클라이언트** | Next.js 페이지 (`/`, `/register`, `/documents`, `/chat`, `/admin`) | 로그인/가입, 대화 화면(SSE 렌더), 문서 업로드, 관리자 화면 |

## 6. 벤더링 구조 (v0.2 추가)

`app/vendor/` 에 4개 PI 패키지 소스(GitHub v0.84.2)를 프로젝트 안에 직접 넣고 자체 빌드한다.

```
app/vendor/
├── package.json              # vendor 공통 의존성 + @earendil-works/pi-client|protocol|tui (npm)
├── build.sh                  # 클린 rebuild 검증 (단계별 빌드 + 모델 JSON/정적 자산 복사)
├── tsconfig.base.json
├── pi-telemetry/             # 텔레메트리v0.84.2 소스 + dist
├── pi-ai/                    # LLM 클라이언트 (Models/provider), 데이터 JSON 포함
├── pi-agent-core/            # Agent/AgentTool/StreamFn 등 핵심
└── pi-coding-agent/          # (빌드 의존성용) — 앱 런타임에서는 미사용
```

- `app/package.json` → `@earendil-works/pi-ai`, `pi-agent-core` 를 `file:./vendor/pi-ai`, `file:./vendor/pi-agent-core` 로 연결.
- `app/tsconfig.json` 의 `exclude`에 `vendor` 추가 (vendor 내부 `.ts` 소스를 tsc가 건드리지 않게).
- 빌드 순서(telemetry → ai → agent-core → coding-agent)는 vendor `build.sh`가 단일 진입점으로 관리.
