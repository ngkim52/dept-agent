# 003. 데이터 모델 (v0.1 초안)

> 주의: RAGFlow 내부 데이터(문서/청크)는 RAGFlow가 소유. 우리 DB는 사용자/부서/대화/권한/매핑만.

## 엔티티
```
User(id, email, name, password_hash, role[user|admin], created_at)
Department(id, name, persona_prompt, ragflow_dataset_id, is_active)
UserDepartment(user_id, department_id)          # 사용자-부서 소속 (N:N)
Document(user_id, department_id, filename, ragflow_doc_id, status, uploaded_at)
Conversation(id, user_id, department_id, title, created_at)
Message(id, conversation_id, role[user|assistant|agent], content, created_at, meta)
PermissionRole / 접근룰 → Q3에 따라 정의
```

## 관계 요약
- 사용자 1:N 문서(업로더 기록용), 사용자 N:N 부서, 사용자 1:N 대화, 대화 1:N 메시지
- **문서는 부서 소속** (권한 확정: 부서 내 공유) → `Document.department_id`
- RAGFlow 쪽 doc id를 문서 레코드에 기록 (이중 기록)
- RAGFlow **데이터셋 = 부서 접근 경계** → 부서 ↔ 데이터셋 1:1

## 권한 규칙 (확정 2026-08-20)
- 사용자는 소속 부서의 데이터셋/문서에만 접근
- 타 부서 자료 접근 불가 (검색 시 해당 부서 데이터셋만 조회)
- 관리자: 전체 접근
- 부서 모델은 N:N 유지 (향후 겸직/2차 부서 대비)

## v0.2 (구현 반영 — Drizzle 스키마, `app/src/lib/db/schema.ts`)

```
departments(id PK, name, persona_key, ragflow_dataset_id, is_active, created_at)
users(id PK, email UNIQUE, name, password_hash, role[user|admin], status[pending|active|rejected], department_id→departments, created_at)
sessions(id PK, token_hash UNIQUE, user_id→users, expires_at, created_at)   # 불투명 토큰 해시 저장
conversations(id PK, user_id→users, department_id→departments, title, created_at)
messages(id PK, conversation_id→conversations, role[user|assistant|system], content, citations(JSON), created_at)
documents(id PK, user_id→users, department_id→departments, filename, ragflow_doc_id, status[uploaded|parsing|done|failed], created_at)
```

### 구현 반영 시 변경점
- **피처별 분리**: `UserDepartment` 매핑 테이블 → MVP는 `users.department_id` 단일 소속 (2차에서 N:N 전환 예정)
- **status 필드 추가**: 가입 승인 흐름(`pending/active/rejected`)
- **sessions 테이블**: 토큰 자체를 저장하지 않고 `token_hash`(sha256)만 보관
- **messages.citations**: RAG 근거 청크를 JSON으로 저장 (SSE `citations` 이벤트와 동일 구조)
