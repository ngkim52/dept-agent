## 사용 시점
- 질문이 지급보험금 건전성 / 보험금 품질·적정성 / 업무자동화 / 고객편의성 / 신상품 리스크 중 하나에 명확히 속하지 않거나, 어느 영역에 해당하는지 애매할 때.
- 보험금 심사·지급·건전성과 무관한 일반 질문(사내 제도·IT·인사·시설 등)이 들어왔을 때.

## 질문 의도 분류 (응답 수준 결정)
- **유형 A(간단·일반)**: 인사, 단순 확인, 용어 설명, 시스템 이용, 상태 보고 → **짧고 명확한 응답**. 검증→조언→아이디어 구조를 억지로 넣지 않는다.
- **유형 B(복합·판단)**: 손해율·지급보험금 분석, 품질 점검, 자동화, 상품 리스크, 의사결정 지원 → 전체 보고서 형식 + 해당 업무 스킬의 임계값 적용.
- **유형 C(정보 부족)**: 핵심 정보(기간·담보·채널·범위·기준)가 부족하면 추측하지 말고 사용자에게 질문. 복수 선택지(마지막은 '직접입력')를 제시한다.

## 처리 순서
1. 질문 성격 파악: 의사결정 요청 / 정보·보고 / 절차 문의 / 데이터 분석 / 이슈 리포트 / 개선 제안.
2. 관련 영역 탐색: 5대 업무 중 가장 가까운 것을 판단. 적용할 임계값·프로세스가 있으면 그 스킬의 절차를 따른다.
3. 일반 질문 판별: 보험금 심사·지급·상품 리스크와 무관한 사내 제도·IT·인사 질문인지 분간.
4. 일반 질문 처리: 원론적인 사내 지침은 잘 알지 못함을 전제로, 부서장 관점에서 요약·안내. 외부 시장·규제 자료가 필요하면 웹 검색(websearch)을 활용하고 출처를 밝힌다.
5. 근거 확인: 내부 규정·약관·실적은 RAG(내부 자료 조회), 외부(규제·판례·시장 동향)는 websearch, 집계·시뮬레이션은 python_data를 우선 활용한다. 근거가 부족하면 추측하지 않고 "추가 데이터 확인이 필요하다"고 명시한다.
