# 요구 시점
- 사용자가 "이런 것을 다룰 스킬을 만들어 줘", "업무 절차 스킬을 추가하고 싶어" 등 새 스킬 생성을 요청할 때
- 기존 스킬을 정리·개선하거나 새 업무 영역을 스킬로 구조화할 때

## 1. 먼저 확인할 것 (명확화)
- 만들 스킬의 **업무 영역·목적**: 어떤 업무/질문에 쓰이는가
- **주요 판단 기준·출력 형식**: 무엇을 어떻게 판단하고, 어떤 형태로 답해야 하는가
- 대상 부서(페르소나)와, 기존 스킬과의 경계(중복 회피)

## 2. 데이터 수집 (관련 참조 우선)
- 기존 스킬(getPersonaSkills)의 이름·설명을 확인해 금지 범위(scope 배제)와 새 스킬과의 관계를 명확히 한다
- 메모리·과거 대화·업무 자료에서 해당 업무의 판단 기준·선례·수치 기준을 수집한다
- 내부 데이터가 부족하면 웹검색(websearch)으로 업계 기준·제도·최신 동향을 보강한다

## 3. 스킬 구조 (SKILL.md 형식)
```
---
name: <스킬 이름>
description: <언제 사용하는지 1~2문장 + 어떤 상황에 라우팅되어야 하는지 + 범위 배제 문구>
---
# 요구 시점
- <이 스킬이 필요한 구체적 상황>
## 판단 기준
- <정량·정성 기준: 언제 어떤 판단을 하는지>
## 데이터 사용
- <내부 RAG/집계 vs 외부 웹검색 구분>
## 출력 예시 (스킬에 따라서 추천안으로 생성)
[요약] → [현황] → [판단·원인] → [권고] → [다음 단계] → [추가 확인]
```
- **description에 발동(라우팅) 조건과 범위 배제**를 명시해 다른 스킬과 겹치지 않게 한다
- 한 스킬에 여러 업무를 몰아넣지 말고 목적이 명확한 단위로 1개씩 만든다

## 4. 검증
- 생성한 스킬이 다른 스킬과 충돌/중복되지 않는지, 질문 분류 시 정확히 라우팅될 수 있는 문구인지 점검한다
- 사용자 확인 후 저장한다 (사용자 승인 없이 임의 저장 금지)
